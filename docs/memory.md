# Организация памяти процессора CSA4

## 1. Назначение и модель памяти

CSA4 использует **Гарвардскую архитектуру**: инструкции и данные находятся в независимых адресных пространствах.

- **IMEM (Instruction Memory)** хранит машинный код, векторы сброса и прерываний, процедуры и обработчики.
- **DMEM (Data Memory)** хранит константы, глобальные и статические переменные, динамические объекты, стек и регистры устройств MMIO.
- **Data Cache** — отдельная быстрая память с копиями блоков DMEM. Она не является частью DMEM и не изменяет его адресное пространство.

| Характеристика | Значение |
|---|---|
| Организация | Harvard |
| Машинное слово | 32 бита (4 байта) |
| Инструкция | 32 бита (4 байта) |
| Разрядность адреса DMEM | 32 бита |
| Адресное пространство DMEM | `0x00000000–0xFFFFFFFF` (2^32 байт) |
| Размер IMEM | 2^16 байт  |
| Адресуемая единица | 1 байт |
| Порядок байтов | Little-endian |
| Модель DMEM | Sparse Memory |

Sparse Memory — разреженная модель: реализация может хранить только используемые адреса, не выделяя физически непрерывный массив размером 4 ГиБ. Адресное пространство при этом остаётся 32-битным.

## 2. Регистры, доступные программе

### 2.1. Регистры общего назначения

| Регистр | Алиас | Назначение |
|---|---|---|
| `R0` | `zero` | Всегда равен нулю; запись игнорируется |
| `R1–R13` | — | Регистры общего назначения |
| `R14` | `sp` | Указатель стека |
| `R15` | `ra` | Адрес возврата |

Каждый регистр имеет ширину 32 бита. Регистры используются для операндов, промежуточных результатов, адресов и временных значений.

### 2.2. Специализированные регистры

| Регистр | Размер | Назначение |
|---|---:|---|
| `PC` | 32 бита | Счётчик команд |
| `IR` | 32 бита | Регистр текущей инструкции |
| `EPC` | 32 бита | Адрес продолжения после прерывания |
| `AR` | 32 бита | Регистр адреса памяти |

Эти регистры не входят в `R0–R15` и не адресуются обычными инструкциями.

## 3. Instruction Memory

IMEM имеет размер 2^16 байт. Инструкция занимает 4 байта, поэтому адрес инструкции должен быть выровнен на границу четырёх байт.

### 3.1. Карта IMEM

| Адрес | Назначение |
|---|---|
| `0x0000` | Reset vector |
| `0x0004` | Input interrupt vector |
| `0x0008` | Зарезервированный слот |
| `0x000C` и далее | Область `.text` |

Каждый вектор занимает одно 32-битное слово. В данной схеме в слоте вектора размещается инструкция перехода к точке входа. Поэтому код запуска и полный обработчик могут находиться в другом месте `.text`.

Процедуры и обработчики прерываний — это машинный код, следовательно, они размещаются в IMEM, обычно в `.text`. Метка процедуры или обработчика обозначает адрес соответствующей инструкции.

В обычном режиме процессор выбирает инструкцию из IMEM по адресу `PC`. При последовательном выполнении `PC` увеличивается на 4. Переходы, вызовы и возвраты изменяют `PC` согласно семантике соответствующих инструкций.

## 4. Data Memory

DMEM имеет 32-битное адресное пространство: `0x00000000–0xFFFFFFFF`.

### 4.1. Карта DMEM

| Область | Начальный адрес | Конечный адрес | Назначение |
|---|---:|---:|---|
| MMIO | `0x00000000` | `0x0000000F` | Регистры устройств |
| Reserved | `0x00000010` | `0x00000FFF` | Зарезервированная область |
| `.rodata` | `0x00001000` | `0x00001FFF` | Неизменяемые константы |
| `.data` | `0x00002000` | `0x00002FFF` | Инициализированные статические данные |
| `.bss` | `0x00003000` | `0x00003FFF` | Неинициализированные статические данные |
| Heap | `0x00004000` | `0xBFFFFFFF` | Динамическая память |
| Reserved | `0xC0000000` | `0xFFEFFFFF` | Зарезервированная область |
| Stack | `0xFFF00000` | `0xFFFFFFFF` | Стек |

Heap растёт к большим адресам, Stack — к меньшим. Эти области не должны пересекаться. Таблица задаёт логическую карту адресного пространства; конкретные ограничения доступа определяются реализацией памяти.

### 4.2. Статические области

- **`.rodata`** — строковые литералы, константные массивы и другие неизменяемые объекты, которым требуется адрес.
- **`.data`** — глобальные и статические переменные с начальными значениями.
- **`.bss`** — глобальные и статические переменные без явных начальных значений. Они должны быть обнулены при запуске, если это предусмотрено загрузчиком/моделью запуска.

Если объект не помещается в отведённую секцию, сборка должна сообщить о переполнении области.

### 4.3. Heap

Heap используется для объектов, размер и время жизни которых определяются во время исполнения.

### 4.4. Stack

Stack используется для временных данных процедур: локальных переменных, сохранённых регистров, аргументов и адресов возврата, если программа сохраняет их в стеке. Стек растёт вниз. 

## 5. Представление данных и адресация

Память побайтно-адресуемая. Для многобайтовых значений используется Little-endian: младший байт располагается по младшему адресу.

## 6. Размещение литералов и констант

Литерал — значение, записанное непосредственно в исходном тексте (`10`, `0x2A`, `'A'`, `"hello"`). Литерал не обязательно получает отдельный адрес в памяти.

### 6.1. Непосредственные значения

Числовой литерал кодируется прямо в поле `imm`, если помещается в него и подходит по семантике инструкции. В I-формате поле `imm` имеет 18 бит.

### 6.2. Статические литералы

Литерал размещается в `.rodata`, если ему нужен адрес, если это строка/массив либо если программа должна читать его как объект памяти. Статические объекты размещаются последовательно; при необходимости выравнивания между ними добавляются неиспользуемые байты (padding).

Строковый литерал хранится как последовательность байтов; для C-строки после последнего символа добавляется `0x00`.

## 7. Размещение переменных

| Категория | Размещение |
|---|---|
| Глобальная/статическая с начальным значением | `.data` |
| Глобальная/статическая без начального значения | `.bss` |
| Локальная переменная, которой нужен адрес или длительное хранение в рамках вызова | Stack |
| Временное значение вычисления | Регистр общего назначения |
| Динамически созданный объект | Heap |

## 8. Процедуры

Процедуры — последовательности машинных инструкций в IMEM, размещаемые в `.text`. Метка процедуры связывается с адресом её первой инструкции.

## 9. Прерывания

Векторы находятся в начале IMEM: `0x0000` — сброс, `0x0004` — входное прерывание, `0x0008` — зарезервированный слот. В слотах располагаются инструкции перехода к коду запуска и обработчику, который размещается в `.text`.

При принятии входного прерывания процессор сохраняет адрес продолжения в `EPC` и передаёт управление через input interrupt vector. Обработчик выполняет необходимые действия и завершает работу инструкцией `IRET`, восстанавливающей `PC` из `EPC`.

`EPC` хранит один адрес возврата. Если вложенные прерывания не поддерживаются, обработчик не должен рассчитывать на автоматическое сохранение нескольких контекстов; необходимые регистры сохраняются программно.

## 10. Memory-Mapped I/O

Младшая область DMEM отображена на регистры устройств:

| Адрес | Имя | Назначение |
|---|---|---|
| `0x00000000` | `INPUT_DATA` | Получение входного байта |
| `0x00000004` | `OUTPUT_DATA` | Вывод младшего байта |
| `0x00000008` | `CYCLE_COUNTER` | Текущий счётчик тактов |

## 11. Data Cache

Data Cache — отдельная быстрая память между процессором и DMEM. Она хранит копии строк данных из DMEM, а не отдельные программные объекты.

| Параметр | Значение |
|---|---:|
| Размер строки | 16 байт |
| Количество строк | 16 |
| Полезная ёмкость | 256 байт |
| Cache Hit | 1 цикл |
| Cache Miss | 10 циклов |
| MMIO | Обход кэша |

Одна строка содержит 16 последовательных байтов. При промахе соответствующая строка загружается из DMEM. Ёмкость вычисляется как `16 × 16 = 256` байт без учёта служебных метаданных.

## 12. Отображение программы на память: сборка и исполнение

### 12.1. Во время сборки

1. Ассемблер разбирает мнемоники, регистры, литералы, метки и директивы.
2. Инструкции кодируются в 32-битные слова и размещаются в IMEM в секции `.text`.
3. Метки процедур и обработчиков связываются с адресами инструкций.
4. Константные объекты, которым требуется адрес, размещаются в `.rodata`.
5. Инициализированные статические переменные размещаются в `.data`, неинициализированные — в `.bss`.
6. Переходы и символьные адреса разрешаются ассемблером/компоновщиком. Если значение не помещается в поле инструкции, используется поддерживаемая последовательность формирования значения либо выдаётся ошибка.
7. Векторы сброса и прерывания связываются с точками входа соответствующего кода.

### 12.2. Во время исполнения

1. После сброса `PC` получает адрес Reset vector `0x0000`.
2. Код вектора передаёт управление к процедуре начальной инициализации, затем — к точке входа программы.
3. Процессор выбирает инструкции из IMEM по `PC`.
4. Арифметические и логические операции используют регистры и immediate-поля.
5. Загрузка и запись обращаются к DMEM либо к устройствам MMIO.
6. Обычные обращения к DMEM обслуживаются через Data Cache; MMIO обходит кэш.
7. `CALL` и `RET` обеспечивают вызов и возврат из процедур.
8. При входном прерывании сохраняется `EPC`, выполняется обработчик, а `IRET` возобновляет прерванное выполнение.
9. Динамические объекты выделяются в Heap программным аллокатором; временные данные вызовов могут размещаться в Stack.
