# Транслятор CSA4

## 1. Назначение

Транслятор CSA4 представляет собой консольное приложение, предназначенное для преобразования исходного кода на языке ассемблера CSA4 в перемещаемый объектный файл.

Транслятор реализует раздельную трансляцию: каждый исходный модуль обрабатывается независимо, а окончательное размещение секций и разрешение адресов символов выполняется на этапе компоновки.

В процессе трансляции выполняются:

1. Предварительная обработка исходного текста.
2. Синтаксический разбор инструкций и директив.
3. Раскрытие псевдоинструкций.
4. Кодирование машинных инструкций.
5. Формирование секций и таблиц символов.
6. Создание записей релокации.
7. Проверка корректности объектного модуля.
8. Сериализация результата.

Результатом работы является объектный файл формата `CSA4-OBJ-2`, содержащий машинный код, данные и служебную информацию для компоновщика.

## 2. Интерфейс командной строки

Транслятор запускается из командной строки.

Общий формат вызова:

```bash
python translator.py <input.s> <output.o>
```

### 2.1. Аргументы

| Аргумент | Описание | Обязательный |
|---|---|---|
| `input.s` | Путь к исходному файлу с ассемблерным кодом | Да |
| `output.o` | Путь к выходному объектному файлу | Да |

Примеры:

```bash
python translator.py program.s program.o
```

```bash
python translator.py program.s program.o
```

```bash
python translator.py program.s program.o
```

## 3. Входные данные

Входными данными является текстовый файл, содержащий программу на языке ассемблера CSA4.

Программа может включать машинные инструкции, псевдоинструкции, метки, директивы, объявления символов, макросы и блоки условной компиляции.

### 3.1. Общая структура исходного текста

Исходный текст состоит из последовательности строк.

Строка может содержать метку, инструкцию, директиву либо комментарий.

Комментарии начинаются символом `;` и продолжаются до конца строки. Символы `;` внутри строковых и символьных литералов не считаются началом комментария.

Операнды инструкций разделяются запятыми.

Пример:

```asm
.text
.global _start

_start:
    movi R1, 10
    movi R2, 20
    add R3, R1, R2
    halt
```

### 3.2. Литералы и идентификаторы

Транслятор поддерживает:

- целочисленные литералы с префиксами систем счисления;
- символьные литералы в одинарных кавычках;
- строковые литералы в двойных кавычках;
- ссылки на символы;

Поддерживаемые escape-последовательности:

| Последовательность | Значение |
|---|---|
| `\n` | Перевод строки |
| `\t` | Табуляция |
| `\r` | Возврат каретки |
| `\0` | Нулевой символ |
| `\\` | Обратная косая черта |
| `\"` | Двойная кавычка |
| `\'` | Одинарная кавычка |

Для строковых данных поддерживается кодировка ASCII.

### 3.3. Адресация памяти

Для инструкций загрузки и сохранения используется форма:

```asm
offset(base)
```

Пример:

```asm
load R1, 4(R2)
store R1, 8(R2)
```

Здесь `base` задаёт базовый регистр, а `offset` — непосредственное значение либо ссылку на символ.

Если смещение отсутствует, оно принимается равным нулю:

```asm
load R1, (R2)
```

## 4. Выходные данные

Результатом трансляции является перемещаемый объектный файл с расширением `.o`.

Файл имеет текстовый формат JSON и идентификатор:

```json
{
  "format": "CSA4-OBJ-2"
}
```

Объектный файл содержит следующие поля:

| Поле | Назначение |
|---|---|
| `format` | Версия формата объектного файла |
| `name` | Имя исходного модуля |
| `sections` | Секции с закодированными инструкциями и данными |
| `symbols` | Таблица определённых символов |
| `equs` | Таблица символьных констант |
| `exports` | Экспортируемые символы |
| `imports` | Внешние символы |
| `vectors` | Объявления обработчиков прерываний |
| `relocations` | Записи релокации |
| `source` | Информация об исходных строках инструкций |

Содержимое секций сохраняется в виде шестнадцатеричной строки байтов.

Каждая секция состоит из фрагментов. Фрагмент содержит поле `org`, определяющее явно заданный адрес размещения либо `null`, и поле `data`, содержащее последовательность байтов.

Для каждого символа сохраняются секция, номер фрагмента и смещение внутри него.

Объектный файл не является готовым исполняемым образом: окончательные адреса определяются компоновщиком.

## 5. Этапы работы транслятора

### 5.1. Предварительная обработка

На первом этапе вызывается метод `preprocess()`.

Он выполняет обработку макросов и условных блоков.

Поддерживаются директивы:

| Директива | Назначение |
|---|---|
| `.macro` | Начало определения макроса |
| `.endm` | Завершение определения макроса |
| `.if` | Условное включение блока |
| `.else` | Альтернативная ветвь |
| `.endif` | Завершение условного блока |

### 5.2. Синтаксический разбор

Для каждой строки выполняются:

1. Удаление комментария.
2. Выделение и регистрация меток.
3. Определение мнемоники инструкции или имени директивы.
4. Разделение операндов.
5. Проверка количества и допустимости операндов.
6. Передача инструкции или директивы соответствующему обработчику.

Метки регистрируются в таблице символов с указанием текущего положения в секции.

Инструкции разрешено размещать только в секции `.text`.

### 5.3. Обработка псевдоинструкций

| Псевдоинструкция | Преобразование |
|---|---|
| `j label` | `jmp label` |
| `call label` | `call R15, label` |
| `mv rd, rs` | `addi rd, rs, 0` |
| `beqz rs, label` | `beq rs, R0, label` |
| `bnez rs, label` | `bne rs, R0, label` |
| `li rd, value` | `lui` и `ori` |
| `la rd, symbol` | `lui` и `ori` |

Инструкции `nop`, `ret`, `iret` и `halt` передаются на кодирование без изменения.

Для `li` и `la` используются старшая и младшая части 32-разрядного значения. При обращении к символу формируются ссылки с модификаторами `%hi` и `%lo`.

### 5.4. Кодирование инструкций

Кодирование выполняется методом `real_instruction()`.

Сначала по мнемонике определяется элемент перечисления `Opcode`.

Затем с помощью таблицы `FORMATS` выбирается формат инструкции.


### 5.5. Формирование секций

Транслятор поддерживает четыре секции:

| Секция | Содержимое |
|---|---|
| `.text` | Машинные инструкции |
| `.rodata` | Константные данные |
| `.data` | Инициализированные данные |
| `.bss` | Неинициализированные данные |

Для управления размещением используются следующие директивы:

| Директива | Назначение |
|---|---|
| `.org` | Начало фрагмента с заданным адресом |
| `.align` | Выравнивание текущего положения |
| `.byte` | Размещение байтов |
| `.word` | Размещение 32-разрядных слов |
| `.ascii` | Размещение строки без нулевого терминатора |
| `.asciz`, `.string` | Размещение строки с нулевым терминатором |
| `.space`, `.zero` | Резервирование области памяти |
| `.equ` | Объявление символьной константы |

Для директивы `.word` требуется выравнивание по границе четырёх байтов.

В секции `.bss` запрещено размещение инициализированных данных.

### 5.6. Формирование таблицы символов

Каждая объявленная метка добавляется в таблицу символов.

Поддерживаются локальные, экспортируемые и внешние символы.

Для управления видимостью используются директивы:

- `.global` и `.globl` — экспорт символа;
- `.extern` — объявление внешнего символа.

Транслятор проверяет повторные определения, конфликты локальных и внешних символов, а также наличие определений для экспортируемых символов.

### 5.7. Формирование релокаций

Поскольку окончательные адреса символов на этапе раздельной трансляции могут быть неизвестны, транслятор создаёт записи релокации.

Окончательное разрешение релокаций выполняется компоновщиком.

### 5.8. Проверка корректности

После обработки исходных строк вызывается метод `check()`.

Он проверяет:

1. Наличие определений всех экспортируемых символов.
2. Корректность объявленных обработчиков прерываний.
3. Наличие определений или внешних объявлений для символов, используемых в релокациях.

Дополнительные проверки выполняются непосредственно при разборе инструкций и директив.

### 5.9. Сериализация результата

После успешной трансляции вызывается метод `to_object()`.

Он формирует словарь Python, содержащий секции, символы, релокации и служебную информацию.

В консольном режиме словарь сериализуется средствами модуля `json` и записывается в указанный выходной файл.

## 6. Обработка ошибок

Транслятор использует исключение `AsmError` для сообщения об ошибках исходного кода и релокаций.

При разборе строк диагностическое сообщение дополняется именем исходного файла и номером строки.

Пример формата сообщения:

```text
error: program.s:12: unknown instruction: example
```

Обрабатываются следующие категории ошибок:

- неизвестная инструкция или директива;
- неизвестный регистр;
- неверное количество операндов;
- некорректный идентификатор;
- неверный формат операнда памяти;
- некорректный литерал;
- выход значения за допустимый диапазон;
- нарушение выравнивания;
- повторное определение символа;
- неопределённый символ;
- некорректное объявление обработчика прерывания;
- недопустимое размещение данных;
- ошибки условной компиляции и макросов.

При обнаружении ошибки формирование объектного представления прекращается.
