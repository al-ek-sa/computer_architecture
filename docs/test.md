# Тестирование CSA4

## 1. Назначение тестирования

Тестирование проекта CSA4 предназначено для проверки корректности
отдельных компонентов инструментальной цепочки и их совместной работы.
Проверяется кодирование и декодирование инструкций, формирование
объектных модулей, компоновка программы, загрузка исполняемого файла и
выполнение программы моделью процессора.

В проекте предусмотрены два уровня автоматизированного тестирования:

-   модульные тесты на базе `pytest`;
-   сквозные тесты (golden tests), запускающие полный путь от исходного
    ассемблерного файла до выполнения программы на модели процессора.

## 2. Модульные тесты

Модульные тесты ISA находятся в файле `test/isa_test.py`. Они проверяют
функции и структуры, определяющие систему команд процессора (каждому файлу соответствует файл *_test.py для проверки данного модуля).

## 3. Сквозное тестирование

Для проверки всей инструментальной цепочки используется
`main/golden_test.py`.

Сквозной тест выполняет следующие этапы:

1.  Загружает описание теста из YAML-файла.
2.  Находит один или несколько исходных файлов ассемблера.
3.  Передаёт каждый исходный файл транслятору `translator.translate`.
4.  Получает объектные модули.
5.  Передаёт модули компоновщику `linker.link`.
6.  Формирует исполняемый бинарный файл с помощью `linker.to_binary`.
7.  Создаёт модель процессора `CPU` и загружает в неё бинарный файл.
8.  При необходимости задаёт расписание поступления входных данных.
9.  Запускает процессор с ограничением максимального количества тактов.
10. Сравнивает фактические результаты с ожидаемыми значениями из
    YAML-файла.

В зависимости от описания теста сравниваются:

-   содержимое исполняемого файла;
-   расположение и содержимое секций;
-   данные, выведенные программой;
-   значения регистров после выполнения;
-   количество затраченных тактов;
-   статистика кэша.

Таким образом, golden-тесты позволяют проверить не только отдельные
функции, но и взаимодействие транслятора, компоновщика, памяти,
устройств ввода-вывода, кэша и модели процессора.

### 3.1. Описание сквозного теста

Описание тестового сценария хранится в YAML-файле. В нём указываются
исходные файлы программы и ожидаемые результаты выполнения.

Ожидаемые результаты могут содержать следующие поля:

  -----------------------------------------------------------------------
  Поле                                Назначение
  ----------------------------------- -----------------------------------
  `out_binary_hex`                    Ожидаемое содержимое исполняемого
                                      файла в шестнадцатеричном виде.

  `out_code_hex`                      Альтернативное поле для проверки
                                      машинного кода.

  `out_sections`                      Ожидаемое содержимое и адреса
                                      секций программы.

  `out_stdout`                        Ожидаемый вывод программы.

  `out_registers`                     Ожидаемые значения регистров.

  `out_cycles`                        Ожидаемое количество тактов
                                      выполнения.

  `out_cache`                         Ожидаемая статистика кэша.
  -----------------------------------------------------------------------
